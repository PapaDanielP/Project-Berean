# Project Berean — Project Overview

## Purpose

Berean is intended to provide a structured knowledge foundation in which information from multiple sources can be represented without collapsing source material, evidence, claims, interpretations, and canonical knowledge into a single undifferentiated fact store.

## Problem

Traditional databases often answer:

> What value is stored for this field?

Berean needs to answer a more difficult question:

> What is being asserted, who or what supports that assertion, where did the supporting information originate, what other sources agree or disagree, and how did Berean derive the resulting knowledge representation?

## Primary capabilities

- Represent canonical entities and events.
- Preserve source-specific identities.
- Capture source records and citations.
- Extract source-grounded evidence.
- Represent claims independently from evidence.
- Associate claims with multiple supporting or contradicting evidence records.
- Represent propositions involving entities, events, relationships, and values.
- Preserve competing claims.
- Support derived and interpretive assertions without presenting them as direct source statements.
- Maintain an auditable provenance chain.

## Initial domain

Biblical and historical information is the initial test domain. Genesis 1–11 is the first substantial stress test because it contains people, genealogy, events, places, chronology, relationships, direct statements, and derived assertions.

## Long-term direction

The architecture should remain domain-extensible. Biblical data is a starting domain, not a hard-coded limitation of the knowledge model.

## Non-goals

Berean is not currently intended to be:

- a generic document-management system
- a sovereign data-residency platform
- an access-control/identity platform
- a blockchain/DKG implementation
- a replacement for primary source editions
- an automated truth oracle
